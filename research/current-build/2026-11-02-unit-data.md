# Build-131544 native unit descriptor index, 2026-11-02

## Scope and evidence

Static extraction of the installed build-131544 NDF archive and exact GUID
joins against two authenticated replays. Research-only: no VM, game launch,
network change, Frida, or REA session participated. Source bytes were read
only; nothing was written to the game directory.

Target archive: `Data/WarGame/PC/131544/NDF_Win.dat`, 24,281,088 bytes,
SHA-256 `172e481d80b4e07c057b43b758191e389e5f79b34d0e566357f768a1e2be151b`.
Tooling: Python 3.14.10, standard library only. Claims are labeled
**confirmed** when read from the archive bytes or a command in this session,
and **inferred** when a supported interpretation is not directly proven.

## What the tool does

`research/aar_unit_index.py` fails closed on the pinned archive digest, walks
the EDAT dictionary, extracts the single `everything.ndfbin` member, decodes
the CNDF class/string/import/property/object tables, and projects unit-class
objects plus the nodes their references reach. It then joins 16-byte
validation GUIDs from opcode `0x07` wire references by exact byte equality.
Replays are joined independently; nothing is merged across replays.

The output is metadata only: class names, descriptor GUIDs, debug and alias
names, module node ids, selector filter node ids, and configured chain paths.
No localized strings are read, no object properties are dumped wholesale.

The ndfbin prefix is 44 bytes: the 40-byte CNDF header, a `u32` declared body
size at +40, then the compressed body at +44. The expanded file is the 40-byte
prefix plus the 21,188,594-byte body, totalling the declared 21,188,634 bytes.

The real streams carry **no zlib end-of-stream marker**: `decompressobj().eof`
is false and the archive's `zlib` data ends without a complete trailer. The
extractor therefore requires the exact declared expanded size and complete
consumption of the supplied input; it does not claim strict zlib stream
completeness. Treat `zlib_eof_marker: false` in the manifest as an observed
property of this build, not corruption and not a completeness check.

## Parsed tables (confirmed)

- 375 classes, 30,362 table strings, 16,219 import paths, 1,996 properties.
- 126,019 objects occupying all 18,622,886 OBJE bytes; the `CHNK` footer agrees
  on the object count.
- 385,391 non-null object references and 421 explicit null references. Every
  non-null reference index is in range and its declared class matches the
  target object; every null reference is the both-fields-`0xffffffff` form.
- Value types decoded without guessing an unknown width; the type histogram is
  retained in the generated index under `parse.value_types`.

## Synthetic fixture correction (test-only)

The fixture, not the production reader, was wrong. The first run was red:

```text
Ran 14 tests
FAILED (errors=5)
ReplayFormatError: CNDF TOC length mismatch
```

Every failing case was `SyntheticIndex.setUp`. Measurement showed the synthetic
expanded file was 1,152 bytes while its own declared total was 1,176: six TOC
records were written as 20 bytes each (4-byte tag + offset + size), so the
table fell 24 bytes short of the reader's required `toc + 8 + 24*count`.
The authentic layout has a reserved `u32` between tag and offset. At expanded
offset 21,188,418 the real first record begins:

```text
4f424a45 00000000 2800000000000000 a6291c0100000000
OBJE      reserved 40               18622886
```

Fixing that exposed two further fixture-only defects, each reproduced and
then corrected: the `UnitListCompany` module object was declared with the
`CompanyUnit` module class instead of
`TUnitListCompanyModuleDescriptor`, and the synthetic EDAT member lacked the
44-byte ndfbin prefix, so the declared body size field was absent. The final
fixture uses the observed compressed container (flag 128, declared body size,
zlib body) and the 24-byte TOC record. These changes are confined to
`tests/test_aar_unit_index.py`; the production extractor and parser were not
edited in this session, and the pinned real archive passed before and after.

The fixture tests mechanics, not current-game compatibility. The hash-pinned
131544 cases are the compatibility evidence.

## Limitations

- Static configuration only. No runtime registry, server acceptance,
  deployment, ownership, or timing evidence.
- A GUID-type join compares 16 configured bytes with 16 wire bytes. It does
  not establish live entity identity; `runtime_identity` is null and
  `identity_status` is `static_guid_join_only`.
- Selector conditions are retained unevaluated. Chains are configured paths,
  not active modules; `conditions_evaluated` is false.
- The embedded decompressed stream lacks a zlib EOF marker. Extraction trusts
  the declared sizes and exact input consumption, not a stream trailer.
- Only the compressed container flag (128) appears in the installed archives
  observed here; the uncompressed branch is unobserved and unverified.
- No localized names are claimed. Debug names, aliases, and raw tokens are
  metadata, not UI text.
- Generated JSON keeps the absolute archive path and is private working
  evidence; it is not published with this note.
